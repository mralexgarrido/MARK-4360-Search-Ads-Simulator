# Contributing to Search Ads Simulator

Improvements to teaching clarity, keyboard access, form feedback, print output, and reproducible documentation are welcome.

For a proposed change, explain the student or instructor problem first. Open a focused branch and keep application behavior changes separate from dependency, hosting, and documentation changes where practical. Preserve the existing lockfiles and base path unless the change explicitly addresses them.

Before a pull request, run the existing build and the relevant checks in [MAINTAINING.md](MAINTAINING.md). Describe what you actually tested and what remains untested. Include a screenshot only when it helps demonstrate a visual change; use fictional data.

Do not commit credentials, environment files, student records, paid-account details, or generated artifacts unrelated to the change. Do not report an exploitable vulnerability with credentials or reproduction details in a public issue. Use an established private maintainer contact for sensitive reports.

This guide does not add or change a software license. Discuss redistribution or substantial reuse with the repository owner.
